# 让角色和手中物件一起通过障碍 · AI 原型任务模板

> 来源：https://gameplayatlas.loopyhop.com/mechanic/movement-carry-object/

```text
你是一名资深游戏原型工程师。请用原创代码与原创占位素材，实现一个可玩的最小原型，验证以下机制。不要复制任何现有游戏的名称、角色、世界观、地图、界面布局、数值表、美术、音频或代码。

## 机制
让角色和手中物件一起通过障碍（Move yourself and a carried object through obstacles）

## 设计目标
自己能过去还不够，还要让手里的物件到达目的地。

## 基础规则
任务要求把场景中的实体物件送到指定位置，物件仍有自己的位置和碰撞。玩家可以抱着走、暂放或抛到另一侧，再让角色跟上；核心是规划人和物件的两条路线，而非比较背包总重量。

## 核心循环
1. 观察物件目的地
2. 规划人和物件的路线
3. 携带、暂放或投递
4. 重新会合并继续搬运

## 关键取舍
- 抱着物件走较远的安全路，还是先把它送过间隙再自己追上？
- 把物件留在开关上能开门，但下一段是否还需要把它带走？

## 可调参数
- 持物时可做的动作：保留全部动作更流畅，限制部分动作会让暂放与转移变得有意义。
- 物件失落后的恢复：就近重置能保留解题节奏；长距离找回会把空间规划变成重复搬运。

## 最小实现建议
在单屏中做一个可拾放方块、一个低台和一个终点按钮；再加入一次必须先送箱再移动角色的间隙。

## 验证方式
检查玩家能否指出下一步先移动人还是物件，并且失败后不必重做已经理解的整段搬运。

## 需要避免
物件卡进地形或掉到取不回的位置会制造无意义重开，需要明确的重置与防卡规则。

## 交付要求
1. 先完成可验证的机制闭环，再考虑表现层；范围控制在单局 3–5 分钟。
2. 所有素材必须原创、程序化生成或使用明确的占位符，不使用第三方游戏资产。
3. 提供运行方式、操作说明、关键参数和验证结果。
4. 如果表现与机制验证冲突，优先保留机制，不增加无关系统。
```
